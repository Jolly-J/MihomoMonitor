# Persistence 持久化层规范文档 (AGENTS.md)

本目录封装基于原生 SQLite3 的本地数据持久化机制，负责流量历史的持久化存储、多维聚合统计与定期清理。

---

## 一、目录职责与边界

- **连接生命周期归档**：
  - 在代理网络连接结束时，将连接的生命周期数据（进程名、目标域名、出站节点、传输字节数、起止时间等）写入 `conn_history` 数据表。
- **高性能聚合查询**：
  - 提供多维报表分析能力，包括按应用、域名、代理节点及历史明细的聚合统计，支持不同的时间窗口过滤（1小时/24小时/7天/全部）。
- **生命周期滚动清理**：
  - 定期清理超期连接日志（默认清理超过 3 天的历史记录），防止 SQLite 文件无限膨胀。

## 三、代码与安全规范（严格遵守）

1. **并发隔离与死锁防护**：
   - 数据库所有读写操作必须派发至专属串行队列 `DispatchQueue(label: "com.mihomo.monitor.db")`。
   - **禁止内部嵌套 `queue.sync`**：公开方法负责调度入队，内部私有执行函数（如 `_fetchStatsPrivate`、`_fetchConnectionLogsPrivate`）直接操作数据库指针，严禁在内部再次调用 `queue.sync`，彻底杜绝死锁。
2. **SQLite 内存生命周期安全**：
   - 所有文本绑定一律使用 `SQLITE_TRANSIENT`，绝不允许使用 `nil`（即 `SQLITE_STATIC`）绑定临时 Swift 字符串指针，防止野指针崩溃。
3. **主线程禁止直接同步调用**：
   - 上层 ViewModel 必须使用后台线程或异步任务调用数据库查询，结果返回主线程更新 UI。
4. **注释要求**：
   - 任何涉及 SQL 语句、表结构变更（Migration）、索引设计或析构生命周期的代码，必须带有详细注释说明。
